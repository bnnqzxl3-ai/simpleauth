# SimpleAuth — регистрация на Fabric-сервере 1.21.1

Серверный мод: пока игрок не вошёл, он заморожен на месте, ослеплён, неуязвим,
не может ломать/ставить блоки, бить мобов, писать в чат, трогать инвентарь
и выполнять любые команды кроме `/register` и `/login`.

Пароли хранятся только в виде PBKDF2-хеша (120 000 итераций, HmacSHA256) со случайной солью.

## Команды

| Команда | Описание |
|---|---|
| `/register <пароль> <пароль>` | регистрация (алиас `/reg`) |
| `/login <пароль>` | вход (алиас `/l`) |
| `/changepassword <старый> <новый>` | смена пароля |
| `/simpleauth info` | сколько аккаунтов в базе (оператор 3) |
| `/simpleauth unregister <ник>` | удалить аккаунт (оператор 3) |
| `/simpleauth reload` | перечитать конфиг и базу (оператор 3) |
| `/simpleauth fix <ник>` | сбросить неуязвимость и полёт игрока (оператор 3) |

## Точка авторизации и возврат

Пока игрок не вошёл, его держат на отдельной точке — удобно, если он вышел в лаве,
в пещере с мобами или в падении. После входа его телепортирует ровно туда, где он
вышел в прошлый раз.

По умолчанию точка стоит на `9388.5 / 67 / -2793.5` в обычном мире. Чтобы поменять —
зайди оператором, встань куда надо и выполни `/simpleauth setspawn`. Отключить —
`/simpleauth removespawn`.

Пока игрок висит на этой точке, ему временно выдаётся право полёта и отключается
гравитация. Без этого сервер сам выкидывает его с сообщением
`Flying is not allowed on this server`. После входа полёт и гравитация возвращаются
в исходное состояние.

Координаты выхода хранятся в `players.json`, поэтому переживают перезапуск сервера.
Если сервер упал прямо во время авторизации, мод это заметит и всё равно вернёт
игрока на его место, а не оставит на точке входа.

## Что ещё происходит при заходе

- Титул на весь экран: «Подиумский сервер» и подсказка снизу.
- После входа — титул «Добро пожаловать» с ником и звук повышения уровня.
- Над хотбаром идёт переливающийся радужный отсчёт с полоской заполнения.
  Скорость перелива — `shimmerSpeed`, отключается через `actionBarShimmer`.
- Неверный пароль отвечает звуком отказа.
- Когда кто-то регистрируется впервые, в чат всем уходит объявление.

Пока игрок не вошёл, в чат каждые несколько секунд приходит напоминание
(интервал — `reminderIntervalSeconds`).

Все тексты и каждый из пунктов отключаются в конфиге:
`showTitles`, `showActionBarTimer`, `playSounds`, `broadcastNewPlayer`,
`returnToLastPosition`.

## Про неуязвимость после входа (исправлено в 1.5.0)

Неуязвимость и право полёта записываются в файл игрока. В версиях до 1.5.0 мод
запоминал их при заходе и возвращал после входа — но если игрока выкидывало по
таймауту или сервер перезапускали прямо во время авторизации, в файл успевало
попасть состояние авторизации. При следующем заходе мод считывал его как
«исходное» и возвращал: игрок оставался бессмертным и с полётом.

Теперь мод не читает прежнее состояние, а выставляет то, что положено режиму игры:
выживание — обычный игрок, творческий — полёт и неуязвимость, наблюдатель — полёт.
Заодно состояние сбрасывается при выходе, если игрок так и не вошёл, так что в файл
ничего лишнего не попадает.

В 1.5.1 к этому добавлен ещё один сохраняемый флаг — разрешение изменять мир.
Без него игрок в выживании ведёт себя как в приключении: блоки не ломаются.

Если игрок застрял именно в режиме приключения, сначала проверь `server.properties`:
при `force-gamemode=true` сервер сам навязывает режим из строки `gamemode=` при
каждом заходе, и мод тут ни при чём.

Тем, кто уже стал бессмертным или не может ломать блоки, поможет `/simpleauth fix <ник>` — он приведёт
игрока в порядок по его режиму игры. Достаточно выполнить один раз.

## Проверка после входа

При выходе мод снимает слепок игрока: режим игры, здоровье, сытость, уровни опыта,
количество занятых слотов и короткий хеш содержимого инвентаря. Слепок лежит в
`players.json` рядом с аккаунтом.

После успешного входа три секунды идёт сверка. На экране висит титул
«няшная проверочка_)))», игрок в это время неуязвим — удобно, если он вышел
в опасном месте. По окончании в чат приходит либо «Проверка пройдена», либо
список расхождений, а операторам онлайн уходит короткое уведомление.

Заодно проверка всегда приводит неуязвимость, полёт и гравитацию к текущему режиму
игры. То есть баг с бессмертием чинится сам при первом же входе, без команд.

Настройки: `verifyAfterLogin`, `verifySeconds`, `verifyInvulnerable`,
`notifyOpsOnMismatch`. Текст титула — `titleVerify` в блоке `messages`.

Слепок снимается только при обычном выходе. Если сервер упал, сверять будет не с
чем и мод об этом честно скажет.

## Префиксы

Команда `/prefix`. Доступна только владельцу — ник указан в конфиге в поле `owner`,
по умолчанию `cursedTraxaL`. Остальные игроки, включая операторов, команду даже
не увидят в подсказках.

```
/prefix ⛏              поставить себе символ
/prefix color green    сменить цвет
/prefix off            убрать
/prefix give Ник ⛏     выдать другому игроку
```

Цвета: `green`, `dark_green`, `aqua`, `gold`, `red`, `light_purple`, `yellow`,
`blue`, `gray` и остальные ванильные.

Под капотом это команды скорборда, поэтому символ появляется сразу в чате,
в списке игроков и над головой. Настройка хранится и в файле мира, и в конфиге
мода, так что переживает перезапуск.

Невидимые модификаторы (U+FE0E и подобные) команда вырезает сама — можно смело
вставлять символ откуда угодно, квадратика не будет.

| | |
|---|---|
| `/prefix` | подсказка по синтаксису |
| `owner` в конфиге | кто может пользоваться командой |

## Шоу по расписанию

В 12:30 и 17:20 всем, кто онлайн и вошёл, запускается пятисекундное шоу:
титул «cursed gang» на весь экран, вспышка, растущее кольцо частиц, столб
пламени и всплески фейерверков под звук маяка. Игрок на это время обездвижен
и неуязвим, после чего здоровье, сытость и горение возвращаются к тому,
что было до начала.

Настройки в списке `shows`:

```json
{
  "enabled": true,
  "time": "12:30",
  "target": "*",
  "title": "cursed gang",
  "subtitle": "",
  "durationSeconds": 5,
  "freeze": true
}
```

`target` — `*` для всех онлайн, либо конкретный ник. Часовой пояс общий,
поле `timeZone` в корне конфига. Каждое шоу срабатывает раз в сутки.
Добавить ещё одно — скопируй блок и поменяй время.

Проверить, не дожидаясь расписания: `/simpleauth show` (оператор 3) — запускает
первое шоу из списка прямо сейчас.

## Переименование предметов

```
/rename &b&lЛедяной клинок
/rename clear
```

Доступна всем игрокам, переименовывает предмет в руке. Работают обычные коды
через `&`: цвета `0`–`9` и `a`–`f`, `l` жирный, `o` курсив, `n` подчёркнутый,
`m` зачёркнутый, `r` сброс. Код цвета сбрасывает начатое форматирование,
как в ванильном чате, поэтому цвет пишется перед стилем: `&b&l`, а не `&l&b`.

Курсив, который майнкрафт добавляет переименованным предметам по умолчанию,
снимается автоматически.

Настройки: `renameMaxLength` (по умолчанию 64 символа) и `renameAllowObfuscated`
для кода `&k` — он выключен, потому что мельтешащий текст в чужих руках быстро
надоедает.

Переименовать можно любой предмет и как угодно, так что подделать «алмазный меч»
из палки труда не составит. На небольшом сервере это обычно не проблема, но при
обмене вещами стоит смотреть на сам предмет, а не на подпись.

## Вознесение при смерти

Когда игрока убивает другой игрок, на месте гибели вспыхивает свет, вокруг тела
закручивается белая спираль, и камера погибшего плавно поднимается на восемь
блоков. Внизу расходится кольцо дыма, вверх тянутся искры. В конце — вспышка
на высшей точке.

Звуковой ряд: глухой раскат трезубца и включение маяка в момент смерти, затем
звон аметиста с нарастающим тоном во время подъёма, и звук повышения уровня
с выключением маяка на вершине. Убийце отдельно звучит тотем.

Респавн обычный: игрок сам жмёт кнопку и появляется на своей точке. Показ идёт
поверх экрана смерти, так что ничего не задерживает.

Видят все, кто рядом: частицы уходят каждому игроку в радиусе 32 блоков,
как и любые обычные частицы в игре.

Про нагрузку. Спираль рисуется через тик, а не каждый; если поблизости никого
нет, частицы не отправляются вовсе. Одновременно идёт не больше шести показов —
на массовой рубке остальные смерти проходят тихо. Всего за одно вознесение
уходит около полусотни частиц, растянутых на две секунды.

Настройки: `deathShowEnabled`, `deathShowOnlyPvp` (по умолчанию только PvP,
поставь false — будет при любой смерти), `deathShowHeight` (8 блоков),
`deathShowSeconds` (2), `deathShowMaxAtOnce` (6).

## Косметика

Две штуки: шляпы и эффекты из частиц. И то и другое рисует сервер, игрокам ничего
ставить не надо.

### Шляпы

Настоящие нарисованные шляпы — цилиндры, короны, ушки и прочее. Технически это
головы игроков с произвольной текстурой, поэтому работают на ванильных клиентах
и ресурспак не нужен.

```
/hat list                    что есть в каталоге
/hat <название>              надеть
/hat off                     снять
/hat add <название> <value>  добавить в каталог (владелец)
/hat remove <название>       убрать из каталога (владелец)
/hat                         надеть на голову предмет из руки
```

Как пополнять каталог: зайди на minecraft-heads.com, найди подходящую шляпу,
на её странице скопируй поле **Value** (длинная строка) и выполни:

```
/hat add cylinder eyJ0ZXh0dXJlcyI6...
```

Дальше носится просто `/hat cylinder`.

Настоящий шлем при надевании шляпы уходит в инвентарь, а не пропадает. Команда
`/hat off` снимает только шляпы из каталога — чужую броню она не тронет, даже
если это голова моба.

Занят слот шлема, так что со шляпой настоящей брони на голове не будет.

### Эффекты

```
/cos list              весь список одной командой
/cos wings             включить крылья
/cos flame             сменить частицы
/cos demon             готовый набор
/cos off               убрать
/cos give Ник halo     выдать другому (только владелец)
```

Команда сама понимает, что ей передали: вид, частицы или набор. Запоминать
разные подкоманды не нужно. Старые `/cos particle <частицы>` и
`/cos combo <набор>` тоже работают.

Тридцать три вида, разбитых по смыслу.

**Вокруг игрока:** `wings` (машущие крылья), `halo` (нимб), `aura` (кольцо у ног),
`helix` (спираль), `orbit` (точки на орбитах), `rings` (три кольца),
`sphere` (сфера), `dome` (купол-щит).

**Движение и следы:** `trail` (след при ходьбе), `comet` (хвост по направлению
движения), `footsteps` (отпечатки под ногами, поочерёдно слева и справа),
`swarm` (рой, снующий вокруг).

**Столбы и вспышки:** `tornado` (вихрь), `vortex` (воронка внутрь),
`pulse` (волна кольцом), `lightning` (ломаная молния), `pillar` (столб света
как у маяка), `fountain` (фонтан из-под ног).

**Фигуры:** `cube` (вращающийся куб), `infinity` (восьмёрка), `star` (звезда),
`crown` (корона), `galaxy` (спиральная галактика), `flower` (цветок),
`clock` (стрелки часов), `dna` (двойная спираль).

**На теле:** `cape` (плащ за спиной, колышется), `horns` (рога с головы),
`ears` (кошачьи ушки, подрагивают), `heartbeat` (двойной толчок на груди),
`runes` (знаки вокруг головы), `bubbles` (пузырьки вдоль тела),
`rain` (дождик сверху).

**Живые** — тут частицы летят сами, а не висят на месте: `burst` (разлёт раз в
пару секунд), `shockwave` (плоская волна по земле), `snow` (снегопад с боковым
сносом), `flies` (дёрганая мошкара), `wisp` (блуждающие огоньки), `spin`
(быстрая тугая спираль у ног), `geyser` (редкие выбросы вверх), `sparkle`
(искры, вспыхивающие вплотную к телу).

Названия подставляются по TAB — жми Tab после `/cos` и листай.

### Своя косметика от первого лица

По умолчанию владелец **не видит** свою косметику — окружающие видят, он нет.
Иначе от первого лица частицы лезут прямо в камеру и мешают играть.

Какой у игрока ракурс, сервер знать не может: перспектива переключается целиком
на клиенте и наружу не передаётся. Поэтому единственный способ — не слать
частицы самому владельцу вообще.

Показать себе: `/cos self`. Команда переключает туда-обратно, настройка
сохраняется отдельно для каждого игрока.

### Готовые наборы

Одной командой ставят и вид, и частицы:

```
/cos combo demon
```

Двадцать штук: `angel`, `demon`, `king`, `knight`, `cat`, `storm`, `void`,
`galaxy`, `inferno`, `frost`, `love`, `ghost`, `nature`, `bees`, `aqua`,
`beacon`, `comet`, `dragon`, `wizard`, `disco`.

### Нагрузка

Каждая частица — отдельный пакет всем, кто рядом, поэтому косметика считается
не каждый тик и с общим потолком:

- `cosmeticsIntervalTicks` — раз во сколько тиков перерисовывать, по умолчанию 3;
- `cosmeticsMaxParticlesPerTick` — предел частиц за проход на всех игроков сразу,
  по умолчанию 150.

Фигуры устроены так, чтобы обходиться минимумом точек: кольца рисуются двумя
бегущими точками вместо десяти, звезда чередует лучи, сфера показывает по
несколько точек за раз. Косметика не считается у наблюдателей и невидимых.

Если сервер всё равно проседает — подними интервал до 5 и опусти потолок до 80.

Частицы: `endrod`, `flame`, `soul`, `enchant`, `heart`, `happy`, `crit`, `cloud`,
`dragon`, `totem`, `spark`, `glow`, `portal`, `note`, `smoke`, `firework`.

Вид и частицы задаются отдельно, так что комбинаций хватает: например
`/cos wings` плюс `/cos particle soul` даст крылья из синего пламени.

По умолчанию `/cos` доступна всем игрокам. Чтобы оставить только себе —
`"cosmeticsOwnerOnly": true` в конфиге. Выбор сохраняется и переживает перезапуск.

## Скрытая выдача снаряжения

Команда `/cg` — название задаётся полем `kitCommand` в конфиге. Доступна и видна
в подсказках только владельцу (`owner`). Выдаёт полный комплект: незеритовая броня
с защитой 5, шипами и починкой, элитры, незеритовый меч, кирка, топор, лопата,
мотыга, плюс алмазный «Резящий клинок» с остротой 30, добычей 1000 и разящим
клинком 1000.

Команда ничего не пишет в лог сервера и не рассылает уведомление операторам:
она не вызывает штатную систему обратной связи, а отправляет короткое сообщение
лично игроку. Выключить целиком — `"kitEnabled": false`.

Само название команды хранится в `config.json`, так что тот, у кого есть доступ
к файлам хостинга, его увидит. Скрыть от файловой системы нельзя.

Если понадобится убрать и следы прочих команд, в майнкрафте для этого есть
`/gamerule logAdminCommands false` и `/gamerule sendCommandFeedback false`.

Про уровни за пределом обычных: добыча 1000 на мече означает огромное количество
выпадающих предметов с каждого моба. На слабом хостинге это способно подвесить
сервер, так что бить толпу таким мечом не стоит.

## Скрытая выдача материалов

Команда `/cgm` — название в поле `materialsCommand`. Как и выдача снаряжения,
видна только владельцу и ничего не пишет в лог.

Раскладывает список материалов по шалкерам, по 27 стопок в каждый, и отдаёт
в инвентарь. Что не влезло — падает под ноги. Шалкеровые ящики из самого списка
выдаются отдельными стопками: положить шалкер внутрь шалкера нельзя.

`/cgm 2` удвоит все количества, максимум 10.

Список правится в конфиге, поле `materials` — обычная пара «идентификатор
предмета: количество». Под другую схему просто перепиши его целиком.

## Режим без физики

```
/cgphys on
/cgphys off
/cgphys
```

Пока режим включён, наковальни не падают, двери и факелы не отваливаются без
опоры, вода не течёт, а листва не осыпается.

Работает в двух местах:

- у любой установки блока снимается флаг «оповестить соседей»;
- отключается осыпание листвы, иначе она исчезает прямо во время вставки.

Важно: перехватывается только путь через `/setblock`. Команда `/fill` делает
пересчёт соседей отдельным проходом, до которого мод не дотягивается. Поэтому
перед вставкой выключи в Litematica `pasteUseFillCommand` — тогда всё пойдёт
через `/setblock` и двери с цветами останутся на месте. Вставка станет медленнее,
зато без потерь.

Порядок при вставке схемы:

```
/cgphys on
/cgq on
```

Вставка. Затем:

```
/cgq off
/cgphys off
/cgleaves <координаты>
```

Важно: режим действует на весь сервер, а не только на твои блоки. Пока он
включён, редстоун и вода будут вести себя неправильно у всех. Обязательно
выключай после вставки. Состояние не сохраняется — после перезапуска сервера
физика всегда включена.

## Закрепление листвы

```
/cgleaves 9318 61 -2980 9380 120 -2920
/cgleaves ~-40 ~-10 ~-40 ~40 ~40 ~40
```

Проходит по области и ставит всем листьям `persistent = true`, а расстояние до
бревна сбрасывает в 1. После этого листва перестаёт осыпаться.

Зачем нужно: майнкрафт удаляет листья, у которых до ближайшего бревна больше
шести блоков, если они не помечены как поставленные вручную. Формат `.schematic`
это свойство не хранит, поэтому после вставки схемы вся листва оказывается
«природной» и постепенно исчезает.

Работает изнутри сервера, без обновлений соседних блоков — за один проход и без
подвисаний. Команда доступна только владельцу.

## Очистка области

```
/cgc 9318 61 -2980 9380 110 -2920
/cgc ~ ~ ~ ~30 ~20 ~30
```

Название в поле `clearCommand`, доступна только владельцу. Стирает всё в
прямоугольнике между двумя точками. Поддерживает `~` — относительные координаты
от своей позиции.

Работает изнутри сервера, без единой команды наружу: в логах не остаётся ничего.
Блоки убираются порциями по 20 тысяч за тик, поэтому сервер не подвисает даже на
большой области. Соседние блоки не пересчитываются, иначе песок и вода
устраивали бы лавину на каждом шаге.

Предел — 3 миллиона блоков за раз, предохранитель от опечатки в координатах.
Отмены нет: снесённое не вернуть.

## Тихий режим

```
/cgq on
/cgq off
/cgq
```

Название в поле `quietCommand`, доступна только владельцу. Выключает два игровых
правила: `logAdminCommands` (запись административных команд в консоль и рассылка
операторам) и `sendCommandFeedback` (ответы команд в чат).

Нужно перед вставкой схемы через Litematica: она отправляет десятки тысяч
`/setblock` и `/fill`, каждая из которых иначе попадёт и в лог, и в чат всем
операторам.

Сама команда `/cgq` в лог не пишется, в отличие от ручного `/gamerule`.

Пока режим включён, не логируются вообще ничьи административные команды,
не только твои. После вставки лучше вернуть `/cgq off`.

Если на сервере стоит WorldEdit, у него своё логирование: в его конфиге есть
`logging.log-commands` и файл `worldedit.log` — их надо выключать отдельно.

## Сессии по адресу

После успешного входа адрес запоминается на `sessionMinutes` минут (по умолчанию 10).
Если игрок за это время перезайдёт с того же адреса, пароль не спрашивают — сразу
пускает. Сессии живут только в памяти: после перезапуска сервера все вводят пароль
заново.

Выключить — `"sessionMinutes": 0`.

Оговорка: сессия привязана к адресу, а не к человеку. Если кто-то сидит в той же
сети (общий Wi-Fi, один роутер), в течение окна он сможет зайти под этим ником без
пароля. Для домашнего сервера это обычно не проблема, но окно лучше не растягивать.

## Оповещение о новом адресе

При входе адрес сверяется со списком известных. Если он встретился впервые —
владельцу (`owner` в конфиге) уходит сообщение в чат и делается запись в лог сервера.
Первый вход после установки не считается новым адресом, иначе оповещение приходило
бы всегда.

По умолчанию отслеживается только аккаунт владельца. Чтобы следить за всеми,
поставь `"newIpAlertsForAll": true`.

Сами адреса нигде не хранятся — в `players.json` пишется только их хеш. В сообщении
адрес показывается частично: `84.19.203.***`. Хранится до восьми последних адресов.

Сбросить список для игрока: `/simpleauth resetip <ник>` (оператор 3). Пригодится,
если оповещения надоели после смены провайдера.

## Запрещённые команды

Список `blockedCommands`, по умолчанию `["team"]`. Такие команды блокируются
для всех игроков, включая операторов и владельца. Из консоли сервера они
по-прежнему работают.

## Как собрать .jar

### Вариант A — через GitHub (ничего не надо ставить на комп)

1. Создай новый репозиторий на GitHub.
2. Залей туда всё содержимое этой папки.
3. Вкладка **Actions** → workflow `build` запустится сам (или нажми *Run workflow*).
4. Когда закончится — внизу страницы запуска скачай артефакт **simpleauth-jar**.
5. Внутри архива нужен файл `simpleauth-2.17.1.jar` (файл `-sources.jar` не нужен).

### Вариант B — локально

Нужен JDK 21 и Gradle 8.x:

```bash
gradle build
```

Готовый файл появится в `build/libs/simpleauth-2.17.1.jar`.

Если у тебя есть Gradle — можно один раз выполнить `gradle wrapper`, тогда дальше
работает `./gradlew build` без установленного Gradle.

## Установка на хостинг

1. На сервере должно быть **ядро Fabric 1.21.1** (в панели хостинга: Server Type →
   Fabric, версия 1.21.1). Если сервер сейчас Vanilla/Paper — переключи на Fabric.
2. В папку `mods/` загрузи два файла:
   - `fabric-api-0.115.1+1.21.1.jar` — скачать с Modrinth (Fabric API для 1.21.1);
   - `simpleauth-2.17.1.jar` — твой мод.
3. Перезапусти сервер.
4. При первом запуске создастся `config/simpleauth/config.json`, база аккаунтов —
   `config/simpleauth/players.json`.

В логе при старте должно быть: `[SimpleAuth] Мод загружен.`

### Важно про offline-mode

Мод имеет смысл, если в `server.properties` стоит `online-mode=false`
(пиратский вход). Аккаунты привязаны к нику, поэтому обязательно поставь также:

```
online-mode=false
enforce-secure-profile=false
```

При `online-mode=true` Mojang уже проверяет игроков, и регистрация не нужна.

## Настройки (`config/simpleauth/config.json`)

```json
{
  "loginTimeoutSeconds": 60,
  "minPasswordLength": 4,
  "maxPasswordLength": 32,
  "maxLoginAttempts": 3,
  "blindnessUntilLogin": true,
  "invulnerableUntilLogin": true,
  "muteChatUntilLogin": true,
  "reminderIntervalSeconds": 5,
  "messages": { "...": "все тексты можно переписать под себя" }
}
```

После правки — `/simpleauth reload` или рестарт.

## Резервные копии

`config/simpleauth/players.json` — единственный файл с аккаунтами. Копируй его,
если переезжаешь на другой хостинг.

## Если при старте ошибка миксина

В редком случае несовпадения версий сервер может ругаться на
`ServerPlayNetworkHandlerMixin`. Тогда открой `src/main/resources/simpleauth.mixins.json`,
очисти список `"mixins": []` и пересобери — мод продолжит работать, но команды
до входа перестанут блокироваться (остальная защита сохранится).
